AI 原生桌面智能体工作台

WorkBuddy：一句话AI 帮你搞定所有繁琐工作

你说一句话，AI 直接在你电脑上干活到交付，下载即用，零部署。

WorkBuddy 是一款 AI 原生的桌面智能体工作台。你可以通过主流移动端 IM 应用下达指令，AI 会在你的电脑上自动完成任务——读文件、做表格、写文档、搭网页，直到把成果交到你手上。

核心能力

  • 理解自然语言——一句话把任务交给它，不用写代码。
  • 自主规划执行——接到目标后自己拆解步骤、调度工具去完成。
  • 多模态任务处理——文档、电子表格、PPT、数据分析都能办。
  • 本地文件操作——在授权文件夹内读取与写入你的本地文件。
  • 多任务并行——可同时开多个任务，互不打断，适合一批活一起推。
  • 结果交付与验收——交付的是可打开、可编辑的文档 / 表格 / PPT，不是一段文字。
使用者说："用 AI 半年，最大的改变不是它更聪明了，而是我终于不用把时间花在复制粘贴、整理格式、反复改稿这些琐事上——这些现在一句话就交给 WorkBuddy 了。"

关于 WorkBuddy：WorkBuddy 是腾讯出品的「全场景 AI 工作台」，官方定位是「AI Agent 办公新范式」。它与日常使用的聊天机器人有着本质区别——不只是对话，还能在授权范围内读取本地文件、编辑文档、执行任务、运行命令，最后交付可验收的成果（文档 / 表格 / PPT / 网页 / 应用）。它和腾讯云面向开发者的 CodeBuddy 同源，但面向的是「把活干完」的全场景职场任务。

第 3 章　第一个任务

启动工作台，跑通你的第一次"派活 — 交付"

3.1　启动 WorkBuddy：认识三栏式工作台

启动后看到三栏布局：左侧为目录 / 知识库，中间为对话区，右侧为结果区与预览区。所有产物与文件变更都在右侧可见。

3.2　三种工作模式

Ask 只问不动；Plan 先规划后执行；Craft 直接执行。新手默认用 Plan 最稳，确认方案再让它动手。

3.3　第一个实战任务：写请假邮件并整理桌面文件

帮我校对并写一封明天请假的邮件草稿（事由：病假，1 天，落款我的名字）； 另外把桌面"待整理"文件夹里的 pdf 按月份归类到 D:\归档，先给我清单再动手。

3.4　观察思考过程与执行轨迹

在对话区看它逐步思考与中间步骤，在右侧看文件变更与产物，确认无误再采纳——这就是"可控可验收"。

第 4 章　三种工作模式详解

Ask 顾问 · Plan 项目经理 · Craft 执行家
本章4.1　Ask 模式：保守的"顾问"4.2　Plan 模式：自动规划的"项…4.3　Craft 模式：精准把控的"…4.4　适用场景与选择策略

4.1　Ask 模式：保守的"顾问"

只回答问题、读取文件、分析信息，不能改任何文件。适合"先看再决定"的场景，比如读代码、看文档、做只分析不改动的活。

4.2　Plan 模式：自动规划的"项目经理"

先分析需求、出方案、拆步骤，确认后再执行。高价值、易出错的任务首选，能显著降低返工。

4.3　Craft 模式：精准把控的"执行家"

直接执行指令，可读写文件、运行命令、生成内容。任务明确且范围安全时使用。

4.4　适用场景与选择策略

模式适合不适合
Ask只读分析、看代码 / 文档需产出文件或操作
Plan易错多步任务，先要方案已很清楚的小任务
Craft明确且范围安全的执行敏感目录 / 不可逆删除 / 对外发送
选择策略：不确定就用 Plan；真只问不碰用 Ask；任务明确且范围安全才用 Craft 一口气干完。

第 5 章　任务、空间与对话管理

把活组织好，才能复用与追溯
本章5.1　任务列表：把一次性使用变成资产5.2　工作空间：先划边界，再放手5.3　对话历史：可控可验收的依据

5.1　任务列表：把一次性使用变成资产

侧边栏按文件夹分组展示所有任务，支持搜索与按状态筛选（进行中 / 已完成）。它的价值不在「记录」，而在让上一次的上下文可以复用。

你会遇到的场景怎么做为什么省事
同一份周报，下周还要再写在上周任务里直接追加「按同样格式出本周版本」，而不是新建任务格式约定、数据来源、语气都不用重新交代
长任务做了半截要下班任务不会丢，第二天从任务列表接着推进不必重新描述背景，AI 仍有前半段上下文
记不清上周让它改了哪些文件打开对应任务，看结果区的「变更」页签逐条列出改了什么，可核对可回退

一个习惯：任务标题写成「对象 + 动作 + 交付物」，比如「Q3 销售数据 → 汇总分析 → 带图 PDF」，一个月后自己还能一眼认出来。

5.2　工作空间：先划边界，再放手

指定一个目录作为工作空间，就等于划定它的文件读写范围——范围外的文件它不碰。这是本地 Agent 最重要的安全阀，比事后检查有效得多。

怎么划分：一个项目一个空间，别把整个 D 盘或者桌面根目录直接给它。空间粒度越细，越界风险越低，回滚也越容易。

做法结果
工作空间 = 某个项目的目录读写可控，产物归档清晰，出错只影响这一块
工作空间 = 整个盘 / 桌面一次误操作可能牵连无关文件，且难以核查

避坑：「工作空间」不等于「只读」。它划定的是范围，能不能写、要不要先确认，仍由 Ask / Plan / Craft 模式决定。两件事要分开想。

5.3　对话历史：可控可验收的依据

多轮上下文会保留，你可以基于已有讨论持续追问、逐步逼近想要的结果，而不必每次都从头解释。

验收时看三处：① 对话区的思考与中间步骤，判断思路对不对；② 结果区的产物，判断成品能不能用；③ 变更记录，判断有没有动到不该动的地方。三处都过一遍，再点采纳。

追问答法：别只说「再改改」，要说清改哪里、往哪个方向改——「图表换成饼图，颜色跟公司 VI 一致，标题改成『Q3 收入构成』」，一次就到位。

WorkBuddy 能力框架：六层闭环

一套用来判断「任务该交给哪一层」的归纳框架，附配置要点
本章为什么需要这个框架六层分层能力架构详解任务卡住了，该查哪一层

为什么需要这个框架

多数通用大模型停留在"对话"层面，能力边界限于问答与文档生成，难以嵌进企业日常办公的真实流程——缺的是一条覆盖"需求收集 → 方案确认 → 素材整合 → 执行产出 → 交付验收"的闭环。

先说明一句：下面这套「六层」是本书作者在实际使用中归纳的理解框架，用来回答"一个任务卡在哪一层、该去哪一层找解法"，不是官方架构文档。官方对扩展能力的说法是四类：专家、技能、连接器、资料库（详见「专家与技能」一章）。

图：WorkBuddy 六层闭环能力框架
小白常用　·　事一出一步交付　·　Ask 检查　·　Plan 审查　·　Craft 执行　·　人工验收

六层分别管什么

01 — 第 1 层：真实任务层

架构最顶层负责需求输入，锁定高频真实办公场景；摒弃无意义的闲聊，聚焦标准化高频办公任务：周报、PPT 制作、网页开发、多来源素材整理、运营任务交付。

这是产品的底层设计逻辑：场景驱动——所有模型、工具、技能、连接器都服务于"真实任务"，而非纯对话需求，直击通用 AI"脱离业务、无法交付"的痛点。

02 — 第 2 层：Ask / Plan / Craft 三段式任务拆解引擎

收到任务后系统不盲目执行，而是用一套标准化三段流程完成"任务拆解 + 风险检查"，构建执行前闸门：

  1. Ask（查看与确认）：主动核查缺失的关键信息（如 PPT 缺数据源、素材缺出处），确认素材需求、需求标准、交付规则，避免信息不全。
  2. Plan（先出方案）：信息确认后生成完整、可审阅的执行方案——含任务步骤、资源清单、交付格式、时间节点、验收标准；支持人工二次编辑，可审阅、可追溯，降低返工成本。
  3. Craft（正式执行）：方案确认后启动完整执行流程，调度底层模型、角色、工具链落地任务——是执行任务的入口。
三段式流程是任务质量的第一道防线，解决 AI"一次性输出不可控、不符合业务标准"的老问题。

03 — 第 3 层：场景理解层

把一句人话翻译成可执行的任务规格：识别这是"写文档"还是"改数据"，判断该调哪个专家、命中哪个技能、要不要联网、输出成什么格式。这一层的好坏，直接决定后面是"一次就对"还是"改八遍"。

你能做的是把话说清：对象（哪份文件）、动作（汇总 / 改写 / 生成）、标准（多长、什么格式、给谁看）。三者齐了，理解层几乎不会跑偏。

04 — 第 4 层：执行与编排层

真正干活的层：拆解子任务、按需调度不同模型、串起工具链（读文件 → 抽结构 → 算数 → 排版 → 导出），并在长任务里维护进度。多步任务能不能一次跑完，看的就是这一层的编排质量。

实用判断：如果任务反复卡在中途（做到一半停了、步骤乱了），通常是任务描述跨度过大。把它拆成两三个子任务分别交付，比指望它一口气做完更稳。

05 — 第 5 层：数据与外部服务层

任务需要的事实从哪来：本地文件、资料库、连接器（飞书 / 腾讯文档等）、联网搜索、企业系统。这一层决定了答案"有依据"还是"凭印象"。

数据源什么时候用注意
本地文件 / 工作空间改自己的文档、表格、代码先在 5.2 里把范围划对
资料库需要跨文档检索、团队共享口径重要结论让它标出处
连接器读写飞书、腾讯文档等外部协作系统回写类操作用 Plan 先确认字段
联网搜索需要最新信息、外部事实明确要求"标注来源"，否则容易混入旧数据

06 — 第 6 层：交付与验收（出口，不是能力层）

严格说这一层不是"能力"，而是所有能力的出口标准：产物必须是可打开、可编辑、可继续加工的文件（docx / xlsx / pptx / 网页 / 应用），而不是一段还得自己复制粘贴的文字。

验收三问：能不能直接用？（格式、命名、完整性）依据站不站得住？（数据来源是否交代）有没有越界？（改了不该改的文件没有）。三问都过，这次任务才算完成。

任务卡住了，该查哪一层

症状大概率卡在怎么救
答得很泛、像百科第 3 层（没说清对象和标准）补上「哪份文件 + 给谁看 + 什么格式」
做到一半停了 / 步骤混乱第 4 层（跨度过大）拆成子任务，先交大纲再交成品
数据不对、引用了旧信息第 5 层（数据源没限定）指定文件 / 资料库，要求标注出处
结果是一段文字，还得自己排版第 6 层（交付标准没提）明确要 docx / xlsx，并说清页数、图表、命名
改错了不该改的文件模式选错（不是框架问题）改用 Plan，先看变更清单再执行

办公三件套的共同工作流

无论什么文档类型，都建议把任务拆成五个问题。很多"AI 做不好"的办公任务，根源不在模型，而在交付标准不清。

对话：帮我出一份团建策划
WorkBuddy：先问清 5 个问题（人数/预算/目标/时长/偏好）再动手。
团建活动策划方案（模板版）
一、活动主题　二、活动解析　三、活动日程
日程表：09:00–09:30 ｜ 09:30–12:00 ｜ …
格式建议：本地文件优先 Word / DOCX、Excel / XLSX、PowerPoint / PPTX；协同编辑用腾讯文档或 kdocs skill；大批量素材用 Markdown Converter 抽取结构；会议整理用魔函会议或会议纪要 Skill。

1　Word：正式文档与方案

适合交给 Word 的任务

  • 正式方案：活动策划、项目方案、营销方案、培训方案
  • 管理文档：制度、通知、申请、会议纪要、复盘报告、周报月报
  • 产品材料：PRD、需求说明、竞品分析、用户访谈总结

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读取材料，列出可用信息和缺失项哪些材料是真实来源，哪些只是参考
2生成文档大纲和写作口径读者是谁、文档是什么、审核由谁执行
3按大纲生成 Word 初稿标题层级、章节顺序、关键段是否完整
4根据反馈润色、补充、删减哪些可试探，哪些必须标"待确认"
5输出可编辑 docx 和修改说明是否能直接发给同事审阅

提示词示例：生成一份团建活动策划 Word

# 直接复制给 WorkBuddy（Plan / Craft 模式） 帮我生成一份公司团建活动策划 Word 文档框架： - 公司约 80 人，包含：活动目标、主题建议、含时间节点的日程安排、 分组与互动建议、预算估算、人员分工、横幅口号与注意事项 - 语气务实、不过度细致，聚焦整体框架与决策点， 具体细节留白由人工填充

2　Excel：从脏数据到能看懂的结论

表格类任务的难点几乎从不在"算"，而在口径：哪几列是数值、空值怎么算、重复行算不算、汇总按哪个维度。把这些先讲清楚，剩下的它会做完。

适合交给 Excel 的任务

  • 清洗：去重、补缺失值、统一日期与单位格式、拆分合并单元格
  • 汇总：按维度透视、同比环比、分组 Top N
  • 呈现：条件格式、图表（折线 / 柱状 / 饼图）、多表联动
  • 产出：导出清洗后的新表，保留原表不动

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读取表头与样本行，报告字段类型和异常（空值、重复、格式乱）字段含义是否理解正确，哪些列是本该是数字却存成了文本
2给出清洗与汇总方案（口径 + 步骤）口径对不对：分母是谁、异常值留不留
3执行并输出新表 + 图表总数跟源表对得上吗（先抽查两三行）
4补充结论句与关键发现结论有没有超出数据支持的范围

提示词示例

# 直接复制给 WorkBuddy（Plan 模式） 读 @销售明细.xlsx（不要改动原文件）： 1. 先告诉我有哪些字段、多少行、哪些列有空值或重复 2. 按「地区 + 月份」汇总销售额，口径说明写清（空值如何处理、退货是否冲减） 3. 生成一张折线趋势图 + 一张地区占比饼图 4. 导出 销售_汇总.xlsx，第一页放结论，第二页放明细

避坑：别让它直接覆盖原始数据文件。要求「另存为新表」，出错还能回头对照。数字类结论务必自己抽查两行，尤其是"合计"和"同比"。

3　PPT：先定结构，再谈好看

AI 做 PPT 最容易翻车的不是设计，是结构空——每页都有一堆字，但没有一条主线。所以顺序必须是：先定「讲给谁、要说服他什么」，再定页面骨架，最后才是配图配色。

适合交给 PPT 的任务

  • 汇报类：周报月报、项目进展、复盘总结、季度经营分析
  • 提案类：方案汇报、竞品分析、产品发布、培训课件
  • 改造类：把一份长文档 / 会议纪要压缩成 10 页汇报稿

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读材料，提炼 3 条主张（想让人记住什么）这三条是不是你真正想说的
2出页面骨架：每页一个标题句 + 要点 + 用图还是用表页数、顺序、逻辑链是否成立
3按骨架生成 pptx（套用统一模板与配色）模板、字号、页脚编号是否统一
4按反馈精简文字、替换配图每页是否还留着"给人念"的长句

提示词示例

# 直接复制给 WorkBuddy（Plan 模式） 把 @Q3复盘.docx 做成 12 页汇报 PPT： - 听众是部门负责人，目标是争取下季度预算 - 结构：现状 3 页 → 问题 2 页 → 举措 4 页 → 预算与预期 2 页 → 结论 1 页 - 每页标题写成一个结论句（不要"现状分析"这种标签） - 先给页面骨架让我确认，再出 pptx

一个反常识的经验：要求"每页标题写成一句结论"（如「华东区贡献了 62% 增量」而不是「区域分析」），成品可用度会高一个档次——因为这逼着它先想清楚每页要证明什么。

WorkBuddy 专家与技能

给 AI 同事换上专业大脑，再装一套标准作业流程
本章01　为什么要分这两层02　专家（Expert）：谁来干03　技能（Skill）：怎么干04　开发自己的技能：从一个人用到一群…05　组合实战：一份季度竞品对标报告06　四类扩展能力怎么分工07　避坑 & 验收清单

前面几章用的都是 WorkBuddy 的"通用能力"。可一旦任务需要行业判断（比如财报分析、合同审阅），或需要固定章法（比如每次都按同一套格式出报告），光靠一句需求描述就不够稳了。WorkBuddy 用两类扩展能力解决这件事：专家（Expert）决定"由谁、用什么视角来做"，技能（Skill）决定"按哪套验证过的流程来做"。

官方定位：专业任务 = 使用专家和技能复用专业知识与工作方法，完成分析、创作、处理等任务。通用能力负责"能干"，专家和技能负责"干得专业、干得一致"。

01　为什么要分这两层

做法实际发生什么适合
只写一句需求通用模型自由发挥，结论随对话波动一次性的简单杂活
配一个专家换成该领域的角色、判断框架与术语体系需要专业结论、行业视角
装一套技能按写死的工作流逐步执行，结果可复现重复执行、有既定 SOP
组合起来最强：专家定"视角"，技能定"流程"，两者叠加就是一位既懂行、又守规矩的 AI 同事。

02　专家（Expert）：谁来干

WorkBuddy 的专家中心内置了覆盖多个方向的专家，包括投资金融、法律合规、营销内容、数据分析、招聘 HR、教育、医疗等（具体数量随版本更新，以客户端「专家中心」实际显示为准）。入口在左侧栏「专家」→ 专家中心，按类别浏览，选中任意一个即可开始一段专门对话。需要多角色协作时，可以启用专家团队（Expert Team）而不是单个专家。

专家中心投资金融法律合规营销内容数据分析更多分类
财报与估值分析竞品对标专家 合同审阅专家数据分析师内容策划
财报与估值分析　·　擅长三表勾稽、估值模型、风险点提炼
按类别浏览 → 选中专家 → 开始对话；一个会话只启用一个专家或专家团队

没主动选专家也没关系：当任务涉及专业判断、深度研究、专门角色或多角色协作时，WorkBuddy 会检索并推荐合适的专家供你确认。

请从专家中心帮我找一位擅长「财报与估值分析」的专家， 用它审我上传的这份 Q3 财报，输出 5 条风险点 + 一页结论。
注意：专家改变的是"判断视角"，不改变文件访问权限。真正动手仍受 Ask / Plan / Craft 三种模式约束。

03　技能（Skill）：怎么干

技能是把验证过的工作流、具体命令、API 用法和用户约定打包成的可复用能力。任务描述一旦命中技能说明，WorkBuddy 会优先加载它、照章执行，而不是凭通用知识临场发挥——这是"每次结果都一致"的关键。

层级存放位置作用范围怎么选
用户级~/.workbuddy/skills/个人，跨所有项目可用默认安装位置
项目级{workspace}/.workbuddy/skills/项目内团队共享需明确说明"项目级"

路径以本机为准：不同版本 / 平台的配置目录名可能是 .workbuddy 或 .codebuddy（例如 ~/.codebuddy/skills/）。别硬记路径——用「列出已安装技能」让它自己报，或直接在文件管理器里看哪个目录实际存在，再决定往哪放。

三种触发方式：

方式例子说明
自动匹配"把这份 PDF 转成 Word"命中技能说明即自动加载，无需手动
斜杠命令/commit、/review-pr显式点名调用，等价于一条斜杠指令
直接点名"用 XX 技能帮我…"指定某个已装技能
帮我搜索并安装一个能把 PDF 转成可编辑 Word 的技能 /review-pr 帮我审一下当前分支的改动 用刚装好的技能，把「报告目录」下的 Q3.pdf 转成 docx，保留表格
生命周期：先搜索再安装 → 可列出 / 禁用已启用技能 → 没有现成技能时，也能引导创建自己的技能（把团队 SOP 沉淀下来）。安装默认落在用户级，团队共用要显式指定项目级。

04　开发自己的技能：从一个人用到一群人用

内置技能覆盖的是通用做法，但真正让效率翻倍的是你自己那套规矩：公司模板、命名约定、审批口径、只许读不许改的边界……这些写进 prompt 每次都要重讲，写进技能则一次生效、长期复用。

不自研会怎样自研技能带来什么
同一套要求每次重新描述，还容易漏写一次，命中即自动加载
模型凭通用知识临场发挥，结果不稳定流程写死，结果可复现、可验收
团队各写各的 prompt，口径不统一一份技能就是一份团队 SOP
公司私有知识，模型本来就没有模板 / schema / 口径随技能一起带上
判断标准：同一件事做过 3 次以上、且有明确"该怎么做"的规矩，就值得做成技能；一次性的杂活不必。

4.1　最简单的技能长什么样

最小技能只要一个目录 + 一个 SKILL.md，其余全是可选。技能按"渐进加载"设计：名称和描述常在上下文里，命中后才读正文，脚本与参考资料按需再取，不会撑爆对话。

weekly-report-format/ └── SKILL.md ← 必需 （可选）scripts/ 可执行脚本，反复重写的代码放这里 （可选）references/ 参考资料、schema、公司制度，用到才读 （可选）assets/ 模板、图标、样板文件，用于产出物

SKILL.md = YAML frontmatter（name + description）+ Markdown 正文。描述决定"什么时候触发"，务必写清适用场景、用第三人称；正文用祈使句写步骤。下面这份可以直接抄：

--- name: weekly-report-format description: This skill should be used when generating or formatting weekly reports, to apply the team's fixed section order, naming and delivery conventions. agent_created: true --- # 周报格式规范 ## 适用场景 生成、整理或改写周报时。 ## 执行步骤 1. 按固定顺序组织章节：本周完成 / 风险与阻塞 / 下周计划 / 需协调事项 2. 每条写成「结论 + 数据」，不写过程描述 3. 文件命名 周报_YYYY-MM-DD_姓名.md，放回当周目录 4. 交付前自检：章节齐全、风险项无遗漏 ## 约束 - 只做格式整理，不改写业务结论与原始数字 - 不联网补充未经确认的数据

4.2　六步做出第一个技能

步做什么要点
1想清楚触发场景写下 2–3 句"用户会怎么说"，这决定 description
2生成骨架用 /skill-creator 引导，或初始化脚本一键生成模板目录；默认落用户级
3写 SKILL.mddescription 写清"何时用"；正文写清"怎么做"；删掉用不上的示例文件
4补可复用资源重复写的代码 → scripts/；长文档 / schema → references/；模板 → assets/
5真实任务里跑一遍看有没有漏步骤、有没有误触发，回头改 SKILL.md
6校验并打包打包脚本会先校验 frontmatter 与目录结构，通过才出 zip
帮我创建一个技能：把团队的周报格式固化下来， 触发场景是"写周报 / 整理周报 / 生成周报"，先给我看 SKILL.md 草案再落盘。
先确认再落盘：让 WorkBuddy 先给 SKILL.md 草案、你确认后再写入文件，避免约定被写歪；改完再用真实任务验证一次。

4.3　共享给同事，再到更广范围

共享不是一步到位，而是按范围逐级外扩：放对层级，比到处发文件省事得多。

范围怎么做谁能用
① 自己用户级 ~/.workbuddy/skills/（默认位置）本人，跨所有项目
② 同项目同事项目级 {workspace}/.workbuddy/skills/，随仓库提交用这个仓库的人，拉取即生效
③ 跨团队定向分发打包成 zip（先校验再打包），走共享盘 / 资料库发给对方拿到包的人，导入或按提示安装
④ 更广范围按平台流程发布 / 上架到推荐市场与社区，他人一句话搜索安装所有能搜到的人
把这个技能改造成项目级，放进当前项目，方便同事拉取后直接用 校验并打包这个技能，生成可分发的 zip 帮我搜索并安装 XXX 技能
递进原则：先自己用稳 → 再进项目仓库给同事 → 再打包跨团队 → 最后才考虑公开发布。每外扩一层，就把说明写得更完整一点。
共享前四查：① 技能里不能有 token / cookie / 密码 / 内网地址 / 个人绝对路径，凭据一律运行时用环境变量注入；② description 是否让同事也能触发；③ 项目级技能进版本库前是否经过评审；④ 公开发布前是否清掉了公司私有信息与内部口径。

03　功能模块拆解

这个成品的完整功能面拆下来是五个模块，前面截图只是其中三段。理解这个拆法，比记住截图更有用——换任何一个行业，模块结构都大同小异。

一、首页

  • 门店管理：支持定位、搜索、切换；切换门店后商品库存与价格联动刷新。
  • 商品搜索：关键词搜索、历史搜索、热门推荐、搜索结果按相关度排序。
  • 运营位：顶部 banner、限时秒杀（带倒计时）、品类快捷入口。

二、商品列表与分类

  • 分类导航：一级分类（粮油副食 / 休闲食品 / 饮料饮品…）+ 二级分类联动。
  • 列表展示：商品图、名称、规格、价格、销量；支持网格 / 列表两种视图。
  • 筛选排序：按销量、价格升降、新品排序；支持价格区间与品牌筛选。

三、商品详情

  • 基础信息：多图、名称、价格（含划线原价）、规格选择、库存状态。
  • 信任信息：销量、已售数据、评价摘要、服务承诺（买贵包赔、极速退款）。
  • 转化动作：加入购物车、立即购买——两按钮的位置和视觉权重是转化关键。

四、购物车与结算

  • 购物车：商品勾选、数量增减、单行小计、全选、合计金额、角标数量提示。
  • 结算：收货地址、配送时间、优惠券抵扣、支付方式、订单确认。

五、账号与售后（原型阶段可只留入口）

  • 登录 / 注册、收货地址管理、订单列表与状态跟踪、退款售后入口。

关键是把"要什么"一次说全，而不是先说"做个商城"再一点点补。下面这段可以整段复制：

# Plan 模式，先生成页面清单与结构，确认后再写代码 做一个 C 端生鲜超市的移动端商城原型（纯前端，可本地打开）： - 页面：首页、门店选择、商品列表、商品详情、购物车、结算 - 风格：红白主色，卡片圆角，移动端 375px 宽 - 首页要有：门店切换、搜索框、banner、品类入口、限时秒杀（带倒计时） - 商品数据用本地 mock json，至少 12 个商品，分 3 个一级分类 - 购物车支持增删改数量和金额合计，状态存 localStorage 先给我页面清单和每个页面的模块结构，我确认后再写代码。

03　二、WorkBuddy 在这个组合里负责执行层

# 这个组合里的分工 1. Obsidian 保存长期知识。 2. WorkBuddy 处理原始资料。 3. review 目录承接 AI 生成的半成品。 4. 我负责最后确认。

04　WorkBuddy 在这个组合里主要做六类事

  • 第一，读取指定范围。例如只读 00-inbox、10-sources、_templates，不要全库扫描。
  • 第二，整理和归类。把实时笔记按主题、项目、资料类型分组，找出重复内容、标注待处理材料。
  • 第三，生成知识卡片。把零散笔记提炼成结构化知识卡片，沉淀进 review 区供人工合并。
  • 第四～六，还包括：补全链接与标签、产出每日/每周摘要、把正式结论回写受保护库（经人工确认后）。
核心原则：只读不写全库保护。让 AI 在 inbox / sources / templates / review 之间流转，正式库（projects、notes）始终人工掌控，既享受自动化，又不丢数据主权。
