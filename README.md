# WorkBuddy 学习手册

一本写给「想把活交给 AI 干完」的人的手册。案例驱动，从零基础到上手。**交付物是一个单文件 HTML**，零依赖、可离线、可直接分享；内容则用 Markdown 维护。

📖 **在线阅读**：<https://davidchenliang.github.io/workbuddy-learning-handbook/>

---

## 怎么改这本书（内容 / 渲染分离）

**只改 `content.md`，不要直接改 `index.html`** —— 后者是渲染产物，下次渲染会被覆盖。

改完保存后跑一行命令（或让 WorkBuddy 帮你跑）：

```bash
python render.py            # 生成 index.html，并打印完整性校验
python render.py --check    # 只校验不写文件
```

零依赖，Python 3 标准库即可，不需要 pip install。

| 文件 | 作用 | 要不要改 |
|---|---|---|
| `content.md` | **全部文字内容**：章节、段落、表格、prompt、提示框 | ✅ 改这里 |
| `figures.html` | 示意图 / 界面截图 / 手机原型，按 `{{fig:ID}}` 引用 | 一般不用 |
| `template.html` | 页面骨架 + CSS 配色 + 打印样式 | 改样式时 |
| `render.py` | 渲染器 + 完整性校验 | 一般不用 |
| `index.html` | 渲染产物（Pages 入口） | ❌ 不要手改 |
| `assets/` | 8.6 四格漫画的原图与压缩图；渲染时自动内嵌为 data URI | 换图时 |
| `WorkBuddy实战手册_20261112.html` | 旧链接跳转页，指向 `index.html` | ❌ 不要改 |

**`content.md` 语法速查**

| 写法 | 效果 |
|---|---|
| `## 章标题 {#ch1 nav="侧栏文字" group}` | 开一章；自动进侧栏目录，`group` 表示分组起点，`nav` 可自定义侧栏文字 |
| `## 章标题 {#ch8 subnav}` | 额外把该章的 `###` 子节列入左侧栏（缩进子链接，每个都指向实际锚点）；第 8 章已启用 |
| `> 副标题` | 章标题下为金色副标题；写在小节内则是金色小字说明 |
| `### 小节 {#s1-1}` / `#### 子标题` | 小节；自动同步到章内「本章」导航 |
| `### 小节 {#s4-3 nav="短标题"}` | 章内导航文字用人工简写（不写 `nav` 时自动截前 19 字 + …） |
| `{{chapternav}}` | 章内导航占位，渲染时自动生成，不用手改 |
| `{{fig:fig-intro-1}}` | 插入 `figures.html` 里的示意图 |
| `{{img:comic-1.jpg}}`（写在 `figures.html` 里） | 把 `assets/` 下的图片内嵌成 data URI，保持单文件可离线 |
| 行首写 `<br>` | 段内硬换行：把 ①②③ 这类连写枚举拆成逐条独占一行（渲染器默认把软换行合并为空格） |
| `:::tip` / `:::warn` / `:::note` / `:::info` | 提示框，以 `:::` 结束 |
| `:::lead` / `:::analogy` / `:::toc` / `:::footer` | 导语框 / 比喻框 / 总目录 / 页脚 |
| fenced 代码块、GFM 表格、`-` 列表、`**加粗**`、行内代码、`[链接](#锚点)` | 常规 Markdown |

- **侧栏目录、章内导航都由渲染器按标题自动生成**：加一章就写一行 `## ... {#新id}`，加一节就写 `### ... {#新id}`，不用手动维护目录。默认侧栏只到章级；给章标题加 `subnav`，该章子节才会出现在侧栏。
- 写 `{{fig:新id}}` 前，先在 `figures.html` 里加一段 `<!-- figure: 新id -->` + HTML，否则渲染会插入一条「缺失示意图」警告。
- 内容里的 `&`、`<`、`>` 请用 HTML 实体（`&amp;` / `&lt;` / `&gt;`）；内联 HTML（如 `<br>`、`<span class="hl">`）可直接写，会原样保留。
- 渲染器会校验：失效锚点、未使用的示意图、未替换的占位符；有问题会拒绝写入 `index.html`。

> `.workbuddy/tools/` 下是一次性抽取脚本，**不要重跑**（它会覆盖 `content.md`）。

## 这本书讲什么

不是产品说明书，而是一本「怎么用」的书。核心判断标准只有一条：**任务有没有被干到交付**。

| 部分 | 内容 |
|---|---|
| 入门篇 | 第 1 章 它和聊天机器人的本质区别 · 第 2 章 安装与登录 · 第 3 章 第一个任务跑通 |
| 进阶篇 | 第 4 章 三种工作模式 · 第 5 章 任务/空间/对话管理 · 第 6 章 办公三件套 · 第 7 章 专家与技能 |
| 示例应用篇 | 第 8 章 八个示例应用（8.1–8.8）：电商商城原型 · Obsidian 自动化工作流 · 资料库问答 · Excel 多表合并（详细例子） · 整理百度网盘 · AI 漫画（含四格成片） · 发布与分享 · 浏览器操作（扩展安装 + 多站比价） |

每章都配了**可复制提示词、边界提醒与验收点**，建议先看边界再动手；示例应用篇的 8 个例子用来说明「能干什么」，不必跟着实跑。

## 关于准确性

- **产品定义、核心能力、工作模式等表述一律以 WorkBuddy 官方文档为准**；与文档不一致时按官方口径理解。
- 官方依据：[WorkBuddy 简介](https://www.workbuddy.cn/docs/workbuddy/Overview)（定义、六项核心能力、与传统 AI 对话的区别）、[新建任务栏](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)（三种工作模式、技能、连接器、权限、@ 浏览器操作）、[右侧边栏](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Right-Sidebar)（浏览器：内置浏览器安装、Chrome / Edge / QQ 浏览器扩展、登录态与受控标签页）、[创建任务](https://www.workbuddy.cn/docs/workbuddy/Create-Task)（任务与上下文）、[资料库](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Library)、[网站应用开发与发布](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/App-Publishing/Web-App)、[定时任务](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Automation-Guide)。
- 三种工作模式的官方名称为 **默认（Agent）／计划（Plan）／仅问答（Ask）**；早期资料里的「Craft」不是官方模式名。
- 文中所有产品界面均为**示意图重建**，不是真实截图。8.6 的四格画面由图像生成模型实际绘制，中文台词为后期叠加，平台自动角标已裁切；它是示例产物，不是产品界面截图。
- 官方未提出分层架构；扩展能力为专家 / 技能 / 连接器 / 资料库四类，作用是「扩展工作能力」，规划、执行与交付本身属于工作台的核心能力。
- 第 1 章的「同事 / 顾问 / 资料柜」只是便于零基础读者理解的比喻，不是官方架构。
- 案例篇涉及的官方功能名：**资料库**（上传 / 剪藏 / 添加到任务）、**发布 / 上线**（预览区「分享」获得独立网站链接，发布即对外公开）、**定时任务**（仅在设定的时间规则触发时执行，本地任务需开机在线、云端任务不能访问本机文件）、**@ 浏览器操作**（设置 > 智能体 > 浏览器操控 → 安装并开启；内置浏览器**无需扩展**，操作自己的 Chrome / Edge / QQ 浏览器需装对应 **WorkBuddy 扩展程序**并确认扩展已连接；输入框输入 `@` 选择，作用于当前任务）；连接器可用范围取决于服务本身能力与授权范围，官方文档未列出具体第三方服务清单，以客户端连接器页面实际显示为准；官方「多模态任务处理」指文档 / 表格 / PPT / 数据分析，另有「音频转文字」，不含视频处理。
- 官方 Overview 未说明 WorkBuddy 与 CodeBuddy 的团队 / 技术关系，书中只讲「定位不同」，不作关系推断；官方核心能力为六项，书中不另立「七类能力」等归纳。
- 产品功能与数量类描述随版本变化，请以客户端实际显示为准。

## 发布清单（推 GitHub / Pages 时）

远端仓库只放成品：**推 `index.html` + `README.md` + 当前版本的 PDF 成片**；`WorkBuddy实战手册_20261112.html` 是旧链接跳转页，已一致可不动。`assets/` 不必推（图片渲染时已内嵌为 data URI）。PDF 由 `index.html` 经浏览器打印导出（A4、无页眉页脚），随版本一起发布，仓库只保留当前版本；漫画的独立图片与 HTML 也不推（已内嵌进书里）。

**一律不推**：`示例输出_3.3_20261117.md`（旧口径，含公司内部路径）、`第8章内容审核_20261117.md` 与 `全书检查报告_20261117.md`（内部审核记录）、`content.md` / `figures.html` / `template.html` / `render.py`（源文件，是否纳入版本管理另行决定）、`.workbuddy/`（备份与记忆）。

推送前先核对远端 live state，避免覆盖在远端做过的改动；推完复查 Pages 是否 HTTP 200。
