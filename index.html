第 1 章　WorkBuddy 是什么

一句话定义，以及它和聊天机器人、编程工具的本质区别

先给一个能落地的定义：WorkBuddy 是腾讯出品的全场景 AI 工作台——你把目标和交付标准说清楚，它就在你自己的电脑上读文件、调工具、改文档，一步步把事情做到可验收的成果，而不是只在对话框里回一段建议。所以判断它有没有干成，看的不是回答漂不漂亮，而是有没有东西真正交到你手上。

和聊天机器人比，差别不在「更聪明」，而在有没有交付物：前者止于文字，后者交出文件、网页或已完成的操作；和 Cursor、Claude Code 这类编程工具比，差别也不在能力强弱，而在任务场景：那些工具围绕代码库工作，WorkBuddy 面向办公、文件、多模态与日常交付。本章沿这两条边界展开——1.1 划清与聊天的分界，1.2 说明与编程工具 CodeBuddy 的定位差异，1.3 用一张选型表划清与编程工具的边界，1.4 按官方口径收拢六项核心能力。读完你应该能用一句话向同事讲清它是什么，也知道哪些活不该派给它。

官方名称对照：官方文档把三种工作模式写作「默认（Agent）／计划（Plan）／仅问答（Ask）」——默认模式可直接修改文件，Plan 先出方案待确认再执行，Ask 只问答不执行。本书为叙述简洁沿用 Agent / Plan / Ask 简称；早期资料里的「Craft」不是官方模式名。

4.1　Ask 模式：保守的"顾问"

只回答问题、读取文件、分析信息，不能改任何文件。适合"先看再决定"的场景，比如读代码、看文档、做只分析不改动的活。

4.2　Plan 模式：自动规划的"项目经理"

先分析需求、出方案、拆步骤，确认后再执行。高价值、易出错的任务首选，能显著降低返工。

4.3　默认（Agent）模式：高效执行并完成你的任务

直接执行指令，可读写文件、运行命令、生成内容。任务明确且范围安全时使用。

4.4　适用场景与选择策略

模式适合不适合
Ask只读分析、看代码 / 文档需产出文件或操作

选择策略：不确定就用 Plan；真只问不碰用 Ask；任务明确且范围安全才用 Agent 一口气干完。

你会遇到的场景怎么做为什么省事
同一份周报，下周还要再写在上周任务里直接追加「按同样格式出本周版本」，而不是新建任务格式约定、数据来源、语气都不用重新交代
长任务做了半截要下班任务不会丢，第二天从任务列表接着推进不必重新描述背景，AI 仍有前半段上下文
记不清上周让它改了哪些文件打开对应任务，看结果区的「变更」页签逐条列出改了什么，可核对可回退

一个习惯：任务标题写成「对象 + 动作 + 交付物」，比如「Q3 销售数据 → 汇总分析 → 带图 PDF」，一个月后自己还能一眼认出来。

5.2　工作空间：先划边界，再放手

指定一个目录作为工作空间，就等于划定它的文件读写范围——范围外的文件它不碰。这是本地 Agent 最重要的安全阀，比事后检查有效得多。

怎么划分：一个项目一个空间，别把整个 D 盘或者桌面根目录直接给它。空间粒度越细，越界风险越低，回滚也越容易。

做法结果
工作空间 = 某个项目的目录读写可控，产物归档清晰，出错只影响这一块
工作空间 = 整个盘 / 桌面一次误操作可能牵连无关文件，且难以核查

避坑：「工作空间」不等于「只读」。它划定的是范围，能不能写、要不要先确认，仍由三种工作模式与权限确认共同决定。两件事要分开想。

5.3　对话历史：可控可验收的依据

多轮上下文会保留，你可以基于已有讨论持续追问、逐步逼近想要的结果，而不必每次都从头解释。

验收时看三处：
① 对话区的思考与中间步骤，判断思路对不对；
② 结果区的产物，判断成品能不能用；
③ 变更记录，判断有没有动到不该动的地方。
三处都过一遍，再点采纳。

追问答法：别只说「再改改」，要说清改哪里、往哪个方向改——「图表换成饼图，颜色跟公司 VI 一致，标题改成『Q3 收入构成』」，一次就到位。

五问工作流打通三件套，把交付标准说清楚 AI 才好使
本章6.1　办公三件套的共同工作流6.2　Word：正式文档与方案6.3　Excel：从脏数据到能看懂的…6.4　PPT：先定结构，再谈好看

6.1　办公三件套的共同工作流

无论什么文档类型，都建议把任务拆成五个问题。很多"AI 做不好"的办公任务，根源不在模型，而在交付标准不清。

对话：帮我出一份团建策划
WorkBuddy：先问清 5 个问题（人数/预算/目标/时长/偏好）再动手。
团建活动策划方案（模板版）
一、活动主题　二、活动解析　三、活动日程

格式建议：本地文件优先 Word / DOCX、Excel / XLSX、PowerPoint / PPTX；协同编辑用腾讯文档；大批量素材用 Markdown 抽取结构；会议录音与记录整理用会议纪要类技能（在技能市场搜索安装后使用）。

6.2　Word：正式文档与方案

适合交给 Word 的任务

  • 正式方案：活动策划、项目方案、营销方案、培训方案
  • 管理文档：制度、通知、申请、会议纪要、复盘报告、周报月报
  • 产品材料：PRD、需求说明、竞品分析、用户访谈总结

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读取材料，列出可用信息和缺失项哪些材料是真实来源，哪些只是参考
2生成文档大纲和写作口径读者是谁、文档是什么、审核由谁执行
3按大纲生成 Word 初稿标题层级、章节顺序、关键段是否完整
4根据反馈润色、补充、删减哪些可试探，哪些必须标"待确认"
5输出可编辑 docx 和修改说明是否能直接发给同事审阅

提示词示例：生成一份团建活动策划 Word

# 直接复制给 WorkBuddy（Plan / Agent 模式） 帮我生成一份公司团建活动策划 Word 文档框架： - 公司约 80 人，包含：活动目标、主题建议、含时间节点的日程安排、 分组与互动建议、预算估算、人员分工、横幅口号与注意事项 - 语气务实、不过度细致，聚焦整体框架与决策点， 具体细节留白由人工填充

6.3　Excel：从脏数据到能看懂的结论

表格类任务的难点几乎从不在"算"，而在口径：哪几列是数值、空值怎么算、重复行算不算、汇总按哪个维度。把这些先讲清楚，剩下的它会做完。

适合交给 Excel 的任务

  • 清洗：去重、补缺失值、统一日期与单位格式、拆分合并单元格
  • 汇总：按维度透视、同比环比、分组 Top N
  • 呈现：条件格式、图表（折线 / 柱状 / 饼图）、多表联动
  • 产出：导出清洗后的新表，保留原表不动

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读取表头与样本行，报告字段类型和异常（空值、重复、格式乱）字段含义是否理解正确，哪些列是本该是数字却存成了文本
2给出清洗与汇总方案（口径 + 步骤）口径对不对：分母是谁、异常值留不留
3执行并输出新表 + 图表总数跟源表对得上吗（先抽查两三行）
4补充结论句与关键发现结论有没有超出数据支持的范围

提示词示例

# 直接复制给 WorkBuddy（Plan 模式） 读 @销售明细.xlsx（不要改动原文件）： 1. 先告诉我有哪些字段、多少行、哪些列有空值或重复 2. 按「地区 + 月份」汇总销售额，口径说明写清（空值如何处理、退货是否冲减） 3. 生成一张折线趋势图 + 一张地区占比饼图 4. 导出 销售_汇总.xlsx，第一页放结论，第二页放明细

避坑：别让它直接覆盖原始数据文件。要求「另存为新表」，出错还能回头对照。数字类结论务必自己抽查两行，尤其是"合计"和"同比"。

6.4　PPT：先定结构，再谈好看

AI 做 PPT 最容易翻车的不是设计，是结构空——每页都有一堆字，但没有一条主线。所以顺序必须是：先定「讲给谁、要说服他什么」，再定页面骨架，最后才是配图配色。

适合交给 PPT 的任务

  • 汇报类：周报月报、项目进展、复盘总结、季度经营分析
  • 提案类：方案汇报、竞品分析、产品发布、培训课件
  • 改造类：把一份长文档 / 会议纪要压缩成 10 页汇报稿

推荐流程

步骤WorkBuddy 做什么人要确认什么
1读材料，提炼 3 条主张（想让人记住什么）这三条是不是你真正想说的
2出页面骨架：每页一个标题句 + 要点 + 用图还是用表页数、顺序、逻辑链是否成立
3按骨架生成 pptx（套用统一模板与配色）模板、字号、页脚编号是否统一
4按反馈精简文字、替换配图每页是否还留着"给人念"的长句

提示词示例

# 直接复制给 WorkBuddy（Plan 模式） 把 @Q3复盘.docx 做成 12 页汇报 PPT： - 听众是部门负责人，目标是争取下季度预算 - 结构：现状 3 页 → 问题 2 页 → 举措 4 页 → 预算与预期 2 页 → 结论 1 页 - 每页标题写成一个结论句（不要"现状分析"这种标签） - 先给页面骨架让我确认，再出 pptx

一个反常识的经验：要求"每页标题写成一句结论"（如「华东区贡献了 62% 增量」而不是「区域分析」），成品可用度会高一个档次——因为这逼着它先想清楚每页要证明什么。

第 7 章　WorkBuddy 专家与技能

给 AI 同事换上专业大脑，再装一套标准作业流程
本章7.1　为什么要分这两层7.2　专家（Expert）：谁来干7.3　技能（Skill）：怎么干7.4　开发自己的技能：从一个人用到一…7.5　组合实战：一份季度竞品对标报告7.6　四类扩展能力怎么分工7.7　避坑 & 验收清单

前面几章用的都是 WorkBuddy 的"通用能力"。可一旦任务需要行业判断（比如财报分析、合同审阅），或需要固定章法（比如每次都按同一套格式出报告），光靠一句需求描述就不够稳了。WorkBuddy 用两类扩展能力解决这件事：专家（Expert）决定"由谁、用什么视角来做"，技能（Skill）决定"按哪套验证过的流程来做"。

官方定位：专业任务 = 使用专家和技能复用专业知识与工作方法，完成分析、创作、处理等任务。通用能力负责"能干"，专家和技能负责"干得专业、干得一致"。

7.1　为什么要分这两层

做法实际发生什么适合
只写一句需求通用模型自由发挥，结论随对话波动一次性的简单杂活
配一个专家换成该领域的角色、判断框架与术语体系需要专业结论、行业视角
装一套技能按写死的工作流逐步执行，结果可复现重复执行、有既定 SOP

组合起来最强：专家定"视角"，技能定"流程"，两者叠加就是一位既懂行、又守规矩的 AI 同事。

7.2　专家（Expert）：谁来干

WorkBuddy 的专家中心内置了覆盖多个方向的专家，包括投资金融、法律合规、营销内容、数据分析、招聘 HR、教育、医疗等（具体数量随版本更新，以客户端「专家中心」实际显示为准）。入口在左侧栏「专家」→ 专家中心，按类别浏览，选中任意一个即可开始一段专门对话。需要多角色协作时，可以启用专家团队（Expert Team）而不是单个专家。

专家中心投资金融法律合规营销内容数据分析更多分类
财报与估值分析竞品对标专家 合同审阅专家数据分析师内容策划
财报与估值分析　·　擅长三表勾稽、估值模型、风险点提炼
按类别浏览 → 选中专家 → 开始对话；一个会话只启用一个专家或专家团队

没主动选专家也没关系：当任务涉及专业判断、深度研究、专门角色或多角色协作时，WorkBuddy 会检索并推荐合适的专家供你确认。

请从专家中心帮我找一位擅长「财报与估值分析」的专家， 用它审我上传的这份 Q3 财报，输出 5 条风险点 + 一页结论。

注意：专家改变的是"判断视角"，不改变文件访问权限。真正动手仍受三种工作模式与权限设置约束。

7.3　技能（Skill）：怎么干

技能是把验证过的工作流、具体命令、API 用法和用户约定打包成的可复用能力。任务描述一旦命中技能说明，WorkBuddy 会优先加载它、照章执行，而不是凭通用知识临场发挥——这是"每次结果都一致"的关键。

层级存放位置作用范围怎么选
用户级~/.workbuddy/skills/个人，跨所有项目可用默认安装位置
项目级{workspace}/.workbuddy/skills/项目内团队共享需明确说明"项目级"

路径以本机为准：不同版本 / 平台的配置目录名可能是 .workbuddy 或 .codebuddy（例如 ~/.codebuddy/skills/）。别硬记路径——用「列出已安装技能」让它自己报，或直接在文件管理器里看哪个目录实际存在，再决定往哪放。

三种触发方式：

方式例子说明
自动匹配"把这份 PDF 转成 Word"命中技能说明即自动加载，无需手动
斜杠命令/commit、/review-pr显式点名调用，等价于一条斜杠指令
直接点名"用 XX 技能帮我…"指定某个已装技能
帮我搜索并安装一个能把 PDF 转成可编辑 Word 的技能 /review-pr 帮我审一下当前分支的改动 用刚装好的技能，把「报告目录」下的 Q3.pdf 转成 docx，保留表格

生命周期：先搜索再安装 → 可列出 / 禁用已启用技能 → 没有现成技能时，也能引导创建自己的技能（把团队 SOP 沉淀下来）。安装默认落在用户级，团队共用要显式指定项目级。

7.4　开发自己的技能：从一个人用到一群人用

内置技能覆盖的是通用做法，但真正让效率翻倍的是你自己那套规矩：公司模板、命名约定、审批口径、只许读不许改的边界……这些写进 prompt 每次都要重讲，写进技能则一次生效、长期复用。

不自研会怎样自研技能带来什么
同一套要求每次重新描述，还容易漏写一次，命中即自动加载
模型凭通用知识临场发挥，结果不稳定流程写死，结果可复现、可验收
团队各写各的 prompt，口径不统一一份技能就是一份团队 SOP
公司私有知识，模型本来就没有模板 / schema / 口径随技能一起带上

判断标准：同一件事做过 3 次以上、且有明确"该怎么做"的规矩，就值得做成技能；一次性的杂活不必。

7.4.1　最简单的技能长什么样

最小技能只要一个目录 + 一个 SKILL.md，其余全是可选。技能按"渐进加载"设计：名称和描述常在上下文里，命中后才读正文，脚本与参考资料按需再取，不会撑爆对话。

weekly-report-format/ └── SKILL.md ← 必需 （可选）scripts/ 可执行脚本，反复重写的代码放这里 （可选）references/ 参考资料、schema、公司制度，用到才读 （可选）assets/ 模板、图标、样板文件，用于产出物

SKILL.md = YAML frontmatter（name + description）+ Markdown 正文。描述决定"什么时候触发"，务必写清适用场景、用第三人称；正文用祈使句写步骤。下面这份可以直接抄：

--- name: weekly-report-format description: This skill should be used when generating or formatting weekly reports, to apply the team's fixed section order, naming and delivery conventions. agent_created: true --- # 周报格式规范 ## 适用场景 生成、整理或改写周报时。 ## 执行步骤 1. 按固定顺序组织章节：本周完成 / 风险与阻塞 / 下周计划 / 需协调事项 2. 每条写成「结论 + 数据」，不写过程描述 3. 文件命名 周报_YYYY-MM-DD_姓名.md，放回当周目录 4. 交付前自检：章节齐全、风险项无遗漏 ## 约束 - 只做格式整理，不改写业务结论与原始数字 - 不联网补充未经确认的数据

7.4.2　六步做出第一个技能

步做什么要点
1想清楚触发场景写下 2–3 句"用户会怎么说"，这决定 description
2生成骨架用 /skill-creator 引导，或初始化脚本一键生成模板目录；默认落用户级
3写 SKILL.mddescription 写清"何时用"；正文写清"怎么做"；删掉用不上的示例文件
4补可复用资源重复写的代码 → scripts/；长文档 / schema → references/；模板 → assets/
5真实任务里跑一遍看有没有漏步骤、有没有误触发，回头改 SKILL.md
6校验并打包打包脚本会先校验 frontmatter 与目录结构，通过才出 zip
帮我创建一个技能：把团队的周报格式固化下来， 触发场景是"写周报 / 整理周报 / 生成周报"，先给我看 SKILL.md 草案再落盘。

先确认再落盘：让 WorkBuddy 先给 SKILL.md 草案、你确认后再写入文件，避免约定被写歪；改完再用真实任务验证一次。

7.4.3　共享给同事，再到更广范围

共享不是一步到位，而是按范围逐级外扩：放对层级，比到处发文件省事得多。

范围怎么做谁能用
① 自己用户级 ~/.workbuddy/skills/（默认位置）本人，跨所有项目
② 同项目同事项目级 {workspace}/.workbuddy/skills/，随仓库提交用这个仓库的人，拉取即生效
③ 跨团队定向分发打包成 zip（先校验再打包），走共享盘 / 资料库发给对方拿到包的人，导入或按提示安装
④ 更广范围按平台流程发布 / 上架到推荐市场与社区，他人一句话搜索安装所有能搜到的人
把这个技能改造成项目级，放进当前项目，方便同事拉取后直接用 校验并打包这个技能，生成可分发的 zip 帮我搜索并安装 XXX 技能

递进原则：先自己用稳 → 再进项目仓库给同事 → 再打包跨团队 → 最后才考虑公开发布。每外扩一层，就把说明写得更完整一点。

共享前四查：
① 技能里不能有 token / cookie / 密码 / 内网地址 / 个人绝对路径，凭据一律运行时用环境变量注入；
② description 是否让同事也能触发；
③ 项目级技能进版本库前是否经过评审；
④ 公开发布前是否清掉了公司私有信息与内部口径。

7.5　组合实战：一份季度竞品对标报告

把"专家定视角 + 技能定流程 + 资料供素材"串成一次任务，是可复用的典型套路。

目标：产出 Q3 竞品对标报告（PPT）。 请启用「竞品对标」专家；用 PPT 技能按公司统一模板生成； 素材只取资料库里 Q3 归档的 3 份材料，不要联网补充。 先给大纲让我确认，再出成品。
步骤用到哪一层它做什么
1专家（Expert）用竞品对标框架确定分析维度
2技能（Skill）按统一模板与生成流程产出 PPT

02　分工：谁负责哪一段

# 这个组合里的分工 1. Obsidian 保存长期知识。 2. WorkBuddy 处理原始资料，成果只落 review 区。 3. 我负责最后确认，确认后才合并进正式库。

03　WorkBuddy 在这个组合里主要做六类事

  • 第一，读取指定范围。例如只读 00-inbox、10-sources、_templates，不要全库扫描。
  • 第二，整理和归类。把笔记按主题、项目、资料类型分组，找出重复内容、标注待处理材料。
  • 第三，生成知识卡片。把零散笔记提炼成结构化知识卡片，沉淀进 review 区供人工合并。
  • 第四，补全双向链接与标签。按既有命名规则补全，不改动原文措辞。
  • 第五，产出每日 / 每周摘要。汇总一段时间内新增与待处理材料，标明来源文件。
  • 第六，回写正式结论。仅在人工确认后，把定稿内容合并进受保护库（projects、notes）。

核心原则：正式库不直接写。让 AI 在 inbox / sources / templates / review 之间流转，半成品只落 review；正式库（projects、notes）由你确认后才合并。这样既享受自动化，又不丢数据主权。

验收点：
① 正式库没有被直接改写；
② review 区里的半成品都标了来源文件；
③ 合并进正式库的每一条都经过你确认。

把 《产品手册》 添加到任务，之后我问产品参数时， 只基于这份资料回答，并在答案里标出依据的章节； 资料里没有就明说「未找到」，不要用通用知识补齐。

口径项本例约定为什么

看完这份盘点，你只需回一句「金额统一不含税，含税那份按我给的换算表处理；日期统一 YYYY-MM-DD；区域按文件名补」。

第二段 · 确认后执行（退出 Plan 回到默认（Agent）模式，官方把「表格处理」列为默认模式的适用场景）

按上一条确认的口径，把三份表合并成 月度汇总.xlsx： 1. 合并明细：统一日期与金额口径，补「区域」列和「来源文件」列，行数 = 三份表之和 2. 异常清单：空值、重复、日期解析不了、金额口径缺确认的行，单列一页，写明行号和原因，不要自行丢弃或推测 3. 汇总页：按「区域 × 品类」汇总数量与金额，另按日期出一条金额趋势折线 4. 第一页放结论（各区域合计、最高品类、口径说明），第二页放汇总，第三页放合并明细，第四页放异常清单 5. 三份原表保持不动，所有新内容只写入 月度汇总.xlsx；写完告诉我总行数，我抽查两行再收

05　边界与验收

边界：
① 官方没有「一键合并并自动校验口径」的承诺，口径必须人来定，金额、税率、退货这类规则不要让它推测。
② 多步骤任务建议 Plan 先出方案；默认权限下「文件修改」等敏感操作需要你逐次确认，别直接开完全访问。

④ 技能是否可用、模型擅长什么以客户端实际显示为准；图表与结论仍要人工抽查两行，尤其是合计与环比。

验收点：
① 合并行数 = 三份表之和（本例 3,325），差异能逐行解释；

8.8　让 WorkBuddy 操作浏览器

装什么、怎么启用、怎么让它在几个网站间替你比价并记下价格趋势

有些活的输入不在本地文件里，而在网页上：查官网更新、核对竞品页面、盯一款商品在几个站点的价格。官方把这项能力叫 @ 浏览器操作，它是当前任务里的一种能力，不是一个独立的「比价 / 采集」功能。这一节把三件事说清楚：要装什么、怎么用、以及一个「多站比价 + 价格趋势」的例子怎么走。

01　先分清两条通路：要装的不是同一样东西

官方提供内置浏览器和独立浏览器两条路，很多人问的「浏览器插件」只属于后一条：

通路要装什么怎么打开适合
WorkBuddy 内置浏览器不用装任何浏览器插件。首次使用前往 设置 > 智能体 > 浏览器操控，点击安装并开启状态开关；安装完成后 Agent 即可使用内置浏览器右侧面板标签栏「+」→「打开浏览器」，网址栏输网址或关键词（官方默认用搜狗搜索）；也可以直接让 Agent 去开公开页面、临时查资料、看更新日志
你自己的 Chrome / Edge / QQ 浏览器等独立浏览器装对应浏览器的 WorkBuddy 扩展程序：同一设置页下方的多浏览器列表 → 选浏览器 → 点右侧「前往安装」→ 在扩展商店添加 → 在浏览器工具栏点 WorkBuddy 扩展图标，确认扩展已连接在对话里描述网页任务，Agent 会在独立浏览器中新建一个受控标签页，或接管你当前已打开的标签页；设置页的浏览器会话列表能查看和切回需要登录态的页面：会员价、券后价、后台、内网

装好之后，Agent 可以打开指定网址、点击页面元素、输入内容、滚动页面或截取屏幕，也可以读取网页的标题、URL 和 DOM 信息；执行过程中右侧面板会实时展示它正在操作的网页，对话流里同步显示操作结果。独立浏览器里登录态会持续保留（切换会话、新建标签页都不丢），按 WorkBuddy 账号隔离，也能主动清除 Cookie 与缓存。受控标签页你仍然可以手动操作，会话结束后它会从设置页列表移除，不影响浏览器正常使用。

为什么比价常要选第二条：电商站的会员价、券后价、登录后可见价，只有你自己浏览器的登录态里才看得到。但也正因为用的是你的登录态——只在自己的电脑上装，派活前把无关的、含敏感信息的标签页关掉，别让它「接管」错页面。

02　怎么用：三步把能力挂到当前任务上

  1. 按上表装好其中一条通路，确认状态开关已开 / 扩展已连接；
  2. 在输入框输入 @，候选列表里选「浏览器操作」，当前任务就自动带上浏览器能力——官方原话是「无需手动描述具体的浏览步骤」；

03　例子：在几个网站间比较心仪商品的价格趋势

先说清一件事：一次任务只能采到「这一刻」的价格。所谓趋势，是把同一套采样重复跑几次、逐次留档，再让 WorkBuddy 基于历史表做对比和折线。官方没有「自动比价 / 价格趋势追踪」这个功能，这是「@ 浏览器操作 + 本地文件 / 表格 + 定时任务」组合出来的做法（定时任务的官方限制见本节末尾）。

第一步 · 把口径写死（最容易翻车的地方）

  • 锁定同一型号 / 规格 / 容量 / 颜色，别让不同链接的变体混进一张表；
  • 写清价格口径：页面标价、券后到手价、是否含运费 / 税费、是否会员价或限时活动，表里要留备注列，别只留一个数字；
  • 每个价格都带来源链接 + 采样时间；页面没显示的写「未找到」，不推测、不用别的站点补齐。

第二步 · 一次采样，全程只读（可复制）

# 输入 @ 选「浏览器操作」，把 3 个商品页网址一起贴进来 商品：随这条消息一起给你的 3 个商品页链接（以链接为准，不要换成相似款）。 逐个打开，只读取页面上确实显示的内容，整理成一张表： 采样时间 / 站点 / 商品全名 / 规格 / 页面标价 / 券后或到手价 / 是否含运费 / 是否会员价或限时活动 / 来源链接 / 备注。 规格不同、价格口径不同的，要在备注里标出来； 页面没显示的字段写「未找到」，不要推测，也不要用别的网站补齐。 只读取和整理，不要登录、加购、下单或提交任何表单。 先把这张表给我看，我确认后再追加到工作空间的「价格记录表」； 每次采样追加新行，保留历史，不要覆盖。

第三步 · 把多次采样变成趋势（可复制）

# 每次要看时开一个普通任务，重跑上面那段采样；累积几次后另开一个任务 读工作空间里的「价格记录表」，按站点各画一条价格折线， 标出最低价出现的日期、当前价与近几次均价的差异； 只基于表里已有的记录下结论，没有数据的日期留空并注明， 不要推测、不要补写「大概是降了」这类判断。

想省掉手动重跑，可以再试 定时任务：把「读取价格记录表、汇总涨跌」这类任务按每天 / 每周定时跑。按官方说明，定时任务仅在设定的时间规则触发时执行，不会因为你提问就跑；本地任务执行期间需保持电脑开机、客户端运行，云端任务无法访问本机文件（所以要读本机表格就用本地任务）；默认权限下无人值守时敏感操作会停在等待确认；官方建议新建后先「立即运行」试跑一次，并审慎设置涉及文件写入 / 删除 / 资金操作的提示词。至于「无人值守时自动跑浏览器采样」能否稳定工作，官方没有作出承诺，先试跑验证再决定要不要长期挂着，别当成既有能力。

04　边界：能读到什么，不能替你做什么

边界：
① 官方说明浏览器操作作用于当前任务，涉及登录、提交表单、对外发布仍受权限模式约束（默认权限下敏感操作需要你逐次确认）；比价请只读取，别让它自动登录、加购、下单、支付或过验证码，遇到登录墙 / 验证就停下交回给你。

③ 页面改版、登录态失效或站点限制自动访问时，取不到就记「本次未取到」和原因，不要猜数；按目标网站的使用条款控制访问频率，别把网页当接口刷。
④ 定时任务无人值守，涉及写文件 / 删除 / 资金的提示词要审慎，并保留可追溯记录。

验收点：
① 每个站点都留了来源链接与采样时间；
② 规格、价格口径一致且已标注；
③ 缺值写「未找到」，没有编造；
